# 0028 · 决定 —— 放弃"空格当普通字符"换行方案

## 状态

已验证(2026-08-17;纯决策,无代码改动)

## 日期

2026-08-17

## 目的

0027 遗留项:"空格当普通字符换行"受 Chromium textarea 布局限制未能实现,并列出
contenteditable 重写 / 逐空格 ZWSP 等备选方案。用户评估后明确表示**放弃该方案**,
当前排版与体验已满足需求,本项正式关闭。

## 关键决策

1. **不做 contenteditable 重写**:代价(编辑/光标/输入法兼容重写 + 内容污染风险)
   远大于收益;行尾空格不换行是浏览器通用行为,当前输入框其余体验(自动增高、
   精确填满换行、删除即时收缩、输入法稳定)已足够好。
2. **不做 ZWSP 注入**:实测不可靠(部分场景仍不换行),且会污染消息内容与编辑体验。
3. **0027 的"遗留 / 后续"条目以本文收口**,不改写历史文档。

## 验证结果

- 无代码改动;typecheck 不受影响(0027 已验证通过)。
- 当前输入框行为(0026 + 0027 合并后):垂直等距、精确填满换行、封顶滚轮翻看、
  删除即时收缩、组词期间不反复换行、运行中发送变停止按钮——均为最终形态。

## 遗留 / 后续

- 无。若未来 Chromium 改变行尾空格处理,或用户需求变化,再重新评估。
